# Kolobot 🤖📁📦

**Kolobot** — це сучасна асинхронна система персонального документообігу та складського обліку на базі Telegram-бота (`aiogram` v3), штучного інтелекту Google Gemini, векторної бази даних ChromaDB, реляційної бази SQLite та вбудованого веб-інтерфейсу.

Бот автоматично розпізнає текст і таблиці з фотографій та PDF-документів (накладні, вимоги, акти, чеки), структурує позиції номенклатури, оновлює залишки на складі, зберігає оригінали та дозволяє здійснювати семантичний пошук (RAG) природною мовою.

Документи обробляються послідовною фоновою чергою з контролем лімітів API, автоматичними повторами при збоях та відновленням незавершених завдань після перезапуску програми.

## 🚀 Головні можливості

- **Розумний OCR та структурування документів**: Розпізнавання фото та PDF за допомогою Google Gemini (`gemini-3.6-flash`). Витягує номер, дату документа, постачальника, повний перелік товарів (SKU, назва, кількість, од. виміру, ціна, сума) та підсумки.
- **Миттєвий прийом документів та статуси обробки**: Файл завантажується і реєструється в базі одразу після надсилання (`queued`), тож документ видно у веб-панелі ще до початку розпізнавання. Кожен документ має статус: `queued` → `processing_ocr` → `processing_emb` → `completed` або `error`.
- **Автоматичне збереження (autosave)**: Після успішного розпізнавання документ самостійно зберігається в архів, векторну базу та складську таблицю — без натискання кнопок підтвердження. У чат надсилається фінальна картка-звіт із розпізнаними позиціями.
- **Послідовна черга з контролем лімітів**: Документи обробляються по одному у фоновий черзі з паузою між завданнями (`QUEUE_ITEM_DELAY_SEC`), що запобігає перевищенню квот Gemini при масовому надсиланні файлів.
- **Стійкість до збоїв**: При помилці розпізнавання виконується до 3 повторних спроб із наростаючим інтервалом (5с → 15с → 30с). Якщо всі спроби вичерпано, документ отримує статус `error` з текстом помилки, а з веб-інтерфейсу його можна повторити однією кнопкою.
- **Відновлення після перезапуску (crash recovery)**: При старті програми всі документи зі статусами `queued`, `processing_ocr` та `processing_emb` автоматично повертаються в чергу обробки.
- **Автоматичний складський облік**: Автоматичне визначення типу операції (Накладна → Прихід / `income`, Вимога/Акт списання → Розхід / `expense`) з миттєвим перерахунком залишків.
- **Мінімальні залишки**: Для кожної позиції можна задати мінімальний залишок; товари, залишок яких опустився нижче, підсвічуються у веб-інтерфейсі та збираються окремим фільтром «Менше мінімального залишку».
- **RAG-архів (семантичний пошук)**: Пошук по вмісту документів природною мовою (`gemini-embedding-001` + ChromaDB). Бот відповідає на питання щодо документів та надає кнопки для миттєвого завантаження оригіналів.
- **Вбудований веб-інтерфейс**: Зручний дашборд на базі Tailwind CSS для перегляду залишків, історії руху товарів, перегляду оригіналів фото/PDF/Excel, фільтрації аномалій та живого перегляду системних логів (SSE).
- **Пул API-ключів (KeyPool)**: Ротація ключів Google Gemini, ковзне вікно лімітів (RPM/RPD), плавний перехід між ключами та автоматичний 60-секундний кулдаун при помилках 429.
- **Захист від дублікатів**: Миттєва перевірка файлів перед обробкою за унікальним хешем, що запобігає повторним витратам квот Gemini. Для альбомів (media group) кожен дублікат отримує такий самий вибір — окреме повідомлення з кнопками.

## 🔄 Три способи ведення та редагування складу

Система Kolobot пропонує **три взаємодоповнюючі варіанти** керування номенклатурою та залишками:

```
                  ┌─────────────────────────────────────────┐
                  │          Складська база (SQLite)        │
                  │       і Векторний архів (ChromaDB)      │
                  └────────────────────┬────────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
  1. TELEGRAM-БОТ              2. EXCEL ІМПОРТ/ЕКСПОРТ        3. РУЧНЕ РЕДАГУВАННЯ
 • Фото / PDF накладних         • Завантаження .xlsx файлів    • Редагування полів у Web UI
 • Вимоги та акти списання      • Пакетне внесення залишків    • Коригування залишків
 • Статуси обробки в чаті       • Мін. залишок у відомості     • Мінімальний залишок позиції
 • Пошук природною мовою        • Авто-мапінг стовпчиків       • Видалення документів з
 • Автозбереження після OCR     • Експорт повної відомості       авто-перерахунком складу
```

### 1. Через Telegram-бота (Оперативний мобільний облік)
Найшвидший спосіб внесення первинних документів безпосередньо з телефону:
- **Як це працює**: Ви фотографуєте або пересилаєте PDF накладної чи вимоги в чат боту.
- **Миттєвий прийом**: Файл одразу завантажується в локальне сховище та реєструється в базі зі статусом `queued`. Бот відповідає: «📥 Збережено. В черзі (#ID)» — документ уже видно у веб-панелі.
- **Живий статус у чаті**: Повідомлення оновлюється по мірі обробки: `🔄 Розпізнавання` → `🧠 Embeddings` → фінальна картка.
- **Автоматична класифікація**:
  - Документи з ключовими словами *«Накладна», «Прибуткова», «Товарна», «ТТН»* автоматично позначаються як **Прихід** (`income`).
  - Документи зі словами *«Вимога», «Вимога-накладна», «Акт списання»* позначаються як **Розхід** (`expense`).
- **Автозбереження**: Після розпізнавання документ зберігається автоматично — в архів, векторну базу (RAG) та складську таблицю. Бот надсилає фінальну картку з розпізнаними позиціями, цінами, сумами та підсумком по складу.
- **Повтори при помилках**: Якщо розпізнавання не вдалося, бот робить до 3 повторних спроб (5с → 15с → 30с) і повідомляє про кожну. Після вичерпання спроб документ отримує статус `error`, а повторити обробку можна з веб-інтерфейсу.
- **RAG-запити**: Можна запитати бота текстом: *«Скільки кабелю на складі?»* або *«Покажи накладну від Епіцентру за вівторок»*.

### 2. Через імпорт та експорт Excel (Масове оновлення та звітність)
Ідеально для початкового наповнення складу, синхронізації з 1С/обліковими системами або періодичної інвентаризації:
- **Імпорт Excel (`.xlsx`)**:
  - У веб-інтерфейсі натисніть кнопку **«Імпорт Excel»** та виберіть файл.
  - Розумний парсер автоматично розпізнає шапку таблиці та мапить назви колонок (`Найменування`, `Номенклатурний номер / SKU`, `Прихід`, `Розхід`, `Залишок`, `Мін. залишок`, `Од. виміру`, `Постачальник`, `Примітки` тощо).
  - Підтримуються як відомості залишків, так і окремі накладні чи вимоги у форматі Excel.
  - Після імпорту відображається детальний звіт: скільки створено нових позицій, скільки оновлено та скільки проведено транзакцій.
- **Експорт Excel (`.xlsx`)**:
  - Кнопка **«Експорт»** у веб-інтерфейсі генерує та завантажує актуальну відомість складу з автопідбором ширини колонок, числовим форматуванням, колонкою «Мін. залишок» та розрахунком підсумків.

### 3. Ручне редагування та аудит через Веб-інтерфейс (Точне коригування)
Повний контроль над даними безпосередньо у браузері (за замовчуванням: `http://127.0.0.1:8000`):
- **Швидке редагування полів товару**:
  - Біля кожного поля (номенклатурний номер, найменування, залишок, мінімальний залишок, одиниця виміру, постачальник, примітки) є іконка олівця.
  - Клік відкриває модальне вікно, де можна змінити значення та вказати примітку/причину коригування.
  - Зміна мінімального залишку також фіксується в історії руху як запис коригування із зазначенням старого та нового значення.
- **Контроль та видалення документів**:
  - У вкладці **«Документи»** можна розгорнути будь-який документ і побачити його точний вплив на склад (які позиції та в якій кількості були додані чи списані).
  - Можливість перегляду оригіналу документа (фото з масштабуванням зуму, PDF або таблиця Excel) та розпізнаного сирого тексту OCR.
  - Видалення документа через кнопку корзини автоматично видаляє пов'язані з ним транзакції та **каскадно перераховує поточні залишки товарів**.
- **Фільтри аудиту складу**:
  - *Менше мінімального залишку*: товари, залишок яких нижче заданого мінімуму (такі рядки також підсвічуються червоним у загальній таблиці);
  - *Від'ємний залишок*: товари, де розхід перевищив прихід.
  - *Без документу*: позиції без прив'язки до первинних документів.
  - *Однакові назви*: виявлення дублікатів товарів з різними SKU.
  - *Скрізь нулі*: позиції з нульовими показниками.

## 🧠 Логіка та архітектура роботи

```
[ Користувач: Telegram ] ─── (Фото / PDF) ───► [ MediaHandler ]
                                                      │
                                          (Перевірка дублікатів)
                                                      ▼
                                        [ DocumentIntakeService ]
                                     (Миттєве завантаження файлу та
                                      запис у БД зі статусом "queued")
                                                      │
                                                      ▼
[ DocumentQueueService ] ◄─── (Черга завдань) ── (Пауза між завданнями)
        │
        ├──► [ GeminiGateway ] ── (KeyPool: ротація ключів) ──► Google Gemini API (OCR)
        │         │
        │         └── (Збій → 3 повтори: 5с → 15с → 30с → статус "error")
        ▼
[ DocStructurer ] ── (Парсинг JSON, визначення типу: Накладна/Вимога)
        │
        ▼
[ Автоматичне збереження ]
        ├──► [ FileStore ] ────── Збереження оригіналу в ./downloads
        ├──► [ VectorStore ] ──── ChromaDB (векторизація для RAG)
        ├──► [ WarehouseDB ] ──── SQLite (товари, транзакції, статус "completed")
        ├──► [ Telegram Bot ] ─── Фінальна картка-звіт у чат
        └──► [ Веб-інтерфейс ] ── Статуси, кнопка повтору, логи

[ Текстове повідомлення ] ──► [ RagService ] ──► Відповідь + Кнопки файлів
```

1. **Отримання медіа**: Бот приймає зображення (JPEG, PNG, WebP) або PDF-документи.
2. **Дедуплікація**: Вираховується унікальний ідентифікатор файлу (`file_unique_id`). Якщо такий файл вже є в базі або в черзі, бот пропонує відкрити старий запис або форсувати збереження. Для альбомів (media group) кожен дублікат отримує такий самий вибір в окремому повідомленні.
3. **Миттєвий прийом**: `DocumentIntakeService` одразу завантажує файл, зберігає його у тимчасове сховище та створює запис у базі зі статусом `queued` — документ стає видимим у веб-панелі ще до початку розпізнавання.
4. **Асинхронна черга**: Завдання потрапляє до `DocumentQueueService`, який обробляє документи строго по одному (FIFO) з паузою між завданнями. Користувач бачить у чаті живий статус: «Розпізнавання…», «Embeddings…». Черга запобігає перевищенню лімітів API при масовому надсиланні фотографій.
5. **OCR та аналіз структури**: Запит направляється через `GeminiGateway` до моделі `gemini-3.6-flash`. ШІ повертає структуровані JSON-дані з полями документа, списком товарів та сирим розпізнаним текстом. При збої виконується до 3 повторних спроб із наростаючим інтервалом; кожна спроба відображається у чаті та в системному лозі.
6. **Автоматичне збереження**: Після успішного розпізнавання дані фіксуються без участі користувача:
   - Оригінал файлу зберігається у локальне сховище `./downloads/`.
   - Текст та метадані документу індексуються у векторній базі ChromaDB (`gemini-embedding-001`).
   - Дані заносяться в реляційну базу SQLite (`warehouse.db`), оновлюючи залишки та створюючи записи транзакцій; статус документа стає `completed`.
   - У чат надсилається фінальна картка-звіт із розпізнаними позиціями.
7. **Обробка збоїв**: Якщо всі спроби вичерпано, документ отримує статус `error` та текст помилки. Такий документ видно у веб-інтерфейсі, де його можна обробити повторно кнопкою «Повторити».
8. **Відновлення після перезапуску**: При старті `DocumentQueueService` перевіряє базу та повертає в чергу всі документи зі статусами `queued`, `processing_ocr` і `processing_emb`, тож обробка не втрачається після аварійного завершення.
9. **RAG-пошук**: При отриманні звичайного тексту від користувача бот здійснює векторний пошук у ChromaDB, формує відповідь через Gemini та додає кнопки для миттєвого завантаження оригіналів знайдених документів.

## 🛠 Покроковий запуск у новому середовищі

### 1. Вимоги до системи
- **Python**: версія `3.9` або вище (рекомендовано `3.11`, `3.12` або `3.13`).
- **Git**: для клонування коду.
- **Доступ до Інтернету**: для роботи з Telegram Bot API та Google Gemini API.

---

### 2. Клонування репозиторію
```bash
git clone <URL_ВАШОГО_РЕПОЗИТОРІЮ>
cd kolobot
```

---

### 3. Створення та активація віртуального середовища

#### Варіант А: Стандартний Python `venv`

**Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**Windows (Command Prompt):**
```cmd
python -m venv .venv
.\.venv\Scripts\activate.bat
```

**Linux / macOS:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

#### Варіант Б: Використання швидкого менеджера пакетів `uv` (рекомендовано)
```bash
# Якщо uv встановлено:
uv venv
# Активація середовища:
# Windows: .\.venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
```

---

### 4. Встановлення залежностей

**Звичайне встановлення через `pip`:**
```bash
pip install --upgrade pip
pip install -r requirements.txt
```
*або встановлення пакету в режимі розробки:*
```bash
pip install -e .
```

**Або через `uv`:**
```bash
uv pip install -r requirements.txt
```

---

### 5. Створення та налаштування файлу `.env`

Скопіюйте приклад конфігурації у новий файл `.env`:

**Windows:**
```cmd
copy .env.example .env
```

**Linux / macOS:**
```bash
cp .env.example .env
```

Відкрийте файл `.env` у будь-якому текстовому редакторі (VS Code, Notepad, Nano) та заповніть обов'язкові змінні (детально описано в наступному розділі).

---

### 6. Запуск програми

Запустіть Kolobot як модуль Python:
```bash
python -m kolobot
```
*або командою:*
```bash
python kolobot/main.py
```

Після успішного старту в консолі з'явиться повідомлення про запуск черги, веб-сервера та бота:
```text
INFO kolobot.queue_service: DocumentQueueService background worker started.
INFO kolobot.web_server: WebServer running on http://127.0.0.1:8000
INFO kolobot.main: kolobot starting for owner_user_id=..., model=gemini-3.6-flash
```

Якщо в базі залишилися необроблені документи з попереднього запуску, у логах з'явиться запис про відновлення:
```text
INFO kolobot.queue_service: Crash recovery: restored and enqueued 2 unprocessed document(s)
```

Відкрийте браузер за адресою **http://127.0.0.1:8000** та напишіть команду `/start` вашому боту в Telegram.

## 🔑 Детальний гайд: Де брати дані для `.env`

Файл `.env` містить ключі доступу, ідентифікатор власника та параметри роботи системи.

### Приклад готового файлу `.env`:
```ini
# --- Обов'язкові налаштування Telegram ---
BOT_TOKEN=7123456789:AAFlk_xyzExampleTokenSecretKey123
OWNER_USER_ID=123456789

# --- Обов'язкові API ключі Google Gemini ---
# Можна вказати один або кілька ключів через кому для ротації та обходу лімітів
GEMINI_KEYS_GENERATE=AIzaSyA1234567890ExampleKeyGen1,AIzaSyB9876543210ExampleKeyGen2
GEMINI_KEYS_EMBED=AIzaSyC1122334455ExampleKeyEmb1,AIzaSyD5566778899ExampleKeyEmb2

# --- Шляхи до сховищ даних ---
CHROMA_PATH=./data/chroma
DOWNLOADS_PATH=./downloads
# Необов'язково: якщо не вказано, файл створюється поряд з CHROMA_PATH
WAREHOUSE_DB_PATH=./data/warehouse.db

# --- Ліміти та параметри пулу ключів ---
RPM_LIMIT=15
RPD_LIMIT=1500
COOLDOWN_SEC=60

# --- Параметри RAG та розпізнавання ---
RAG_TOP_K=3
RAG_MAX_DISTANCE=1.2
CONFIRM_TIMEOUT_SEC=600
GEMINI_GENERATE_MODEL=gemini-3.6-flash
GEMINI_EMBED_MODEL=gemini-embedding-001

# --- Параметри черги обробки ---
QUEUE_ITEM_DELAY_SEC=3

# --- Налаштування веб-інтерфейсу ---
WEB_ENABLED=true
WEB_HOST=127.0.0.1
WEB_PORT=8000
```

### Детальна інструкція по кожному параметру:

#### 1. `BOT_TOKEN` (Токен Telegram-бота)
- **Що це**: Унікальний токен для авторизації вашого бота в мережі Telegram.
- **Де отримати**:
  1. Відкрийте Telegram і знайдіть офіційного бота [@BotFather](https://t.me/BotFather).
  2. Натисніть `/start` і надішліть команду `/newbot`.
  3. Введіть назву для вашого бота (наприклад, `Мій Склад`).
  4. Введіть системне ім'я користувача (username), яке обов'язково має закінчуватися на `bot` (наприклад, `my_warehouse_kolo_bot`).
  5. BotFather надішле повідомлення з червоним або виділеним рядком токена вигляду: `7123456789:AAFlk_xyzExampleTokenSecretKey123`.
  6. Скопіюйте його та вставте в `BOT_TOKEN`.

#### 2. `OWNER_USER_ID` (Числовий Telegram ID власника)
- **Що це**: Ваш особистий числовий ID користувача в Telegram.
- **Чому це критично важливо**: Kolobot є **приватною системою**. Спеціальний шар безпеки (`AccessMiddleware`) блокує будь-які запити від сторонніх користувачів, які спробують написати боту. Лише користувач із цим ID матиме доступ до файлів, складу та команд.
- **Де отримати**:
  1. У Telegram знайдіть будь-якого бота для перегляду ID, наприклад:
     - [@userinfobot](https://t.me/userinfobot)
     - [@RawDataBot](https://t.me/RawDataBot)
     - [@GetIDsBot](https://t.me/GetIDsBot)
  2. Натисніть `/start`.
  3. Бот покаже ваш числовий ідентифікатор (наприклад, `Id: 456789012`).
  4. Вставте це число в `OWNER_USER_ID`.

#### 3. `GEMINI_KEYS_GENERATE` та `GEMINI_KEYS_EMBED` (Ключі Google Gemini API)
- **Що це**: Безкоштовні (або платні) ключі доступу до моделей Google Gemini AI.
  - `GEMINI_KEYS_GENERATE`: Використовується для OCR розпізнавання тексту з фото/PDF, структурування сутностей та генерації відповідей на RAG-запити (`gemini-3.6-flash`).
  - `GEMINI_KEYS_EMBED`: Використовується для побудови векторних ембеддінгів документів та пошукових запитів (`gemini-embedding-001`).
- **Де отримати**:
  1. Перейдіть на портал [Google AI Studio](https://aistudio.google.com/).
  2. Увійдіть під своїм Google-акаунтом.
  3. Натисніть кнопку **«Get API key»** у лівому меню.
  4. Натисніть **«Create API key»** (можна вибрати існуючий або створити новий Google Cloud проєкт).
  5. Скопіюйте згенерований ключ (починається на `AIzaSy...`).
- **💡 Порада щодо пулу ключів**:
  - Ви можете створити кілька ключів (наприклад, під різні Google-проєкти або акаунти) і вказати їх через кому: `AIzaSyKey1,AIzaSyKey2,AIzaSyKey3`.
  - Вбудований менеджер `KeyPool` буде автоматично розподіляти навантаження між ними, що дозволяє суттєво підвищити ліміти безкоштовного тарифу (Free Tier).
  - Ключі для Generate та Embed можуть бути як однаковими, так і розділеними для ізоляції квот.

#### 4. Шляхи до даних (`CHROMA_PATH`, `DOWNLOADS_PATH`, `WAREHOUSE_DB_PATH`)
- `CHROMA_PATH`: Директорія для файлів векторної бази ChromaDB. Обов'язкова змінна (у `.env.example` — `./data/chroma`).
- `DOWNLOADS_PATH`: Директорія, куди бот зберігає оригінали отриманих фотографій, PDF-файлів та текстові дампи розпізнаного OCR. Обов'язкова змінна (у `.env.example` — `./downloads`).
- `WAREHOUSE_DB_PATH`: Шлях до файлу бази даних SQLite з таблицями номенклатури, документів та транзакцій. Необов'язковий: якщо не заданий, файл `warehouse.db` створюється в тій самій директорії, що й `CHROMA_PATH` (за замовчуванням `./data/warehouse.db`).
- *Примітка*: Всі необхідні директорії створюються автоматично при першому запуску програми.

#### 5. Параметри лімітів, черги та моделей
- `RPM_LIMIT`: Максимальна кількість запитів на хвилину (Requests Per Minute) на один ключ (за замовчуванням `15`).
- `RPD_LIMIT`: Добовий ліміт запитів (Requests Per Day) на один ключ (за замовчуванням `1500`).
- `COOLDOWN_SEC`: Час тимчасового блокування ключа у секундах при отриманні відповіді HTTP 429 (Rate Limit Exceeded) (за замовчуванням `60`).
- `QUEUE_ITEM_DELAY_SEC`: Пауза в секундах між обробкою сусідніх документів у черзі (за замовчуванням `3.0`). Допомагає не перевищувати ліміти Gemini при масовому надсиланні файлів.
- `RAG_TOP_K`: Кількість найбільш релевантних фрагментів документів, що передаються в контекст Gemini під час відповіді на запитання (за замовчуванням `3`).
- `RAG_MAX_DISTANCE`: Поріг косинусної відстані для відсікання нерелевантних результатів (за замовчуванням `1.2`).
- `CONFIRM_TIMEOUT_SEC`: Час очікування підтвердження картки в секундах (за замовчуванням `600`). Наразі зарезервовано: оскільки документи зберігаються автоматично, параметр не впливає на обробку.
- `GEMINI_GENERATE_MODEL`: Модель Gemini для OCR та генерації відповідей. У `.env.example` вказано `gemini-3.6-flash`; якщо змінну не задано, використовується `gemini-2.5-flash`.
- `GEMINI_EMBED_MODEL`: Модель для побудови ембеддінгів. У `.env.example` вказано `gemini-embedding-001`; якщо змінну не задано, використовується `text-embedding-004`.

#### 6. Веб-інтерфейс (`WEB_ENABLED`, `WEB_HOST`, `WEB_PORT`)
- `WEB_ENABLED`: `true` — запускати вбудований веб-сервер разом з ботом, `false` — вимкнути.
- `WEB_HOST`: IP-адреса для прив'язки веб-сервера (`127.0.0.1` для локального доступу або `0.0.0.0` для доступу з локальної мережі чи сервера).
- `WEB_PORT`: Порт веб-інтерфейсу (за замовчуванням `8000`).

## 📱 Команди Telegram-бота

| Команда | Опис |
|---|---|
| `/start` | Перевірка доступу та привітальне повідомлення. |
| `/help` | Довідка щодо формату надсилання документів та доступних функцій. |
| `/status` | Детальний звіт про стан: кількість файлів у черзі обробки (активні та очікуючі), картки, що очікують рішення, та стан кожного API-ключа в пулах Generate і Embed (доступний, кулдаун, ліміт). |
| `/list` | Перегляд останніх збережених документів в архіві. |
| `/delete <id>` | Видалення документа за його ID з архіву, векторної бази та файлового сховища. |
| `/clear` | Екстрене скасування всіх активних фонових задач обробки, очищення черги документів, видалення незбережених карток і очищення тимчасових файлів. |
| **Текстове повідомлення** | Семантичний пошук по базі документів (RAG). Бот відповідає на запитання та додає кнопки для отримання файлів-першоджерел. |
| **Фото або PDF** | Миттєве збереження файлу та постановка в чергу розпізнавання (статус `queued`). Далі — автоматичне збереження в архів і склад та фінальна картка-звіт у чаті. |

## 🌐 Веб-інтерфейс

Вбудований веб-сервер надає зручний інтерфейс для моніторингу та керування:

### 1. Вкладка «Склад»
- **Таблиця залишків**: Відображення номенклатурного номера (SKU), назви товару, сумарного приходу, розходу, поточного залишку (з колірним виділенням), мінімального залишку, одиниці виміру, постачальника та приміток.
- **Підсвічування дефіциту**: Рядки, залишок яких менший за мінімальний, виділяються червоним із попереджувальним значком.
- **Історія руху (Транзакції)**: Клік на будь-який рядок товару розгортає повну історію його операцій (дата, номер документа, операція Прихід/Розхід, кількість, джерело, накопичувальний залишок).
- **Ручне редагування**: Кнопки-олівці для миттєвого редагування будь-яких атрибутів товару, включно з мінімальним залишком.
- **Кнопки «Імпорт Excel» та «Експорт»**: Швидкий обмін даними у форматі `.xlsx`.
- **Швидкі фільтри**:
  - *Менше мінімального залишку* (товари, які час закуповувати);
  - *Від'ємний залишок* (дефіцит / помилка розходу);
  - *Без документу* (товари без прив'язаних накладних чи вимог);
  - *Однакові назви* (дублікати номенклатури);
  - *Скрізь нулі* (неактивні позиції).
- **Лічильники фільтрів**: Кожен фільтр показує кількість позицій, що під нього підпадають.

### 2. Вкладка «Документи»
- **Реєстр документів**: Список усіх завантажених файлів із зазначенням типу (`Фото`, `PDF`, `Excel`), типу документу (`Накладна`, `Вимога`, `Коригування`), дати завантаження, номеру документа та кількості створених транзакцій.
- **Статус обробки**: Кожен документ має бейдж стану — `⏳ В черзі`, `🔄 Розпізнавання`, `🧠 Embeddings`, `✅ Готово`, `❌ Помилка` (з текстом помилки у підказці).
- **Розумне автооновлення (smart polling)**: Поки є документи в обробці, таблиця сама оновлюється кожні 3 секунди; коли всі завершені — оновлення зупиняється і підтягуються актуальні залишки складу.
- **Кнопка «Повторити»**: Для документів зі статусом `❌ Помилка` доступна кнопка повторної обробки — документ скидається у статус `queued` і повертається в чергу.
- **Інтерактивний перегляд**:
  - Перегляд фото з підтримкою масштабування (Zoom In/Out, коліщатко миші) та переглядом вилученого тексту OCR.
  - Перегляд PDF-файлів.
  - Інтерактивний перегляд таблиць Excel з підсвічуванням рядків.
  - Для документів у черзі або в обробці замість тексту показується відповідний статус-плейсхолдер.
- **Вплив на склад (Doc Impact)**: Клік на документ розгортає список товарів, на які цей документ вплинув (+прихід або -розхід).
- **Видалення документа**: Видаляє документ та автоматично відновлює правильні залишки на складі.

### 3. Вкладка «Log» (Термінал логів у реальному часі)
- Живий стрім системних подій через SSE (Server-Sent Events).
- Фільтрація за рівнями логування (INFO, SUCCESS, WARN, ERROR).
- Пошук по тексту логів та автопрокрутка до нових записів.

## 🛡 Безпека та конфіденційність

- **Ізоляція доступу**: Бот реагує виключно на повідомлення та натискання кнопок від облікового запису з ID `OWNER_USER_ID`. Усі інші запити відхиляються без обробки.
- **Локальне зберігання**: Усі документи, бази даних SQLite та векторні індекси ChromaDB зберігаються локально на вашому комп'ютері або сервері у відповідних папках (`./data` та `./downloads`).
- **Google Gemini API**: Дані надсилаються в Gemini виключно для виконання операцій OCR та пошуку відповідно до стандартної політики конфіденційності Google API.
